# 갤럭시 2대 기내모드 Bluetooth E2E

## 목적과 합격 기준

동일 APK를 설치한 갤럭시 2대가 모바일 데이터와 Wi-Fi 없이 Bluetooth Classic RFCOMM만으로 협동 원정과 2인 결투를 진행·복구할 수 있는지 검증한다. 솔로 플레이는 이번 범위에 포함하지 않는다.

최종 합격 조건은 다음과 같다.

- P0 시나리오 15개가 모두 통과한다. 조건부 통과는 허용하지 않는다.
- 연결 성공까지 15초 이하, 재연결과 상태 복원까지 20초 이하를 목표로 한다.
- 30턴 또는 30분 연속 실행 중 크래시, ANR, 턴 불일치, 카드·체력 불일치가 0건이어야 한다.
- 두 기기의 12자리 `호환 코드`가 같고 연결 표시가 `VERIFYING`에서 `CONNECTED`로 전환되어야 한다.
- 기내모드가 켜져 있고 Wi-Fi·모바일 데이터가 꺼진 상태를 스크린샷으로 증명한다.

## 준비

1. 두 기기에서 기존 앱을 삭제하지 말고 같은 APK를 덮어 설치한다. 기존 저장 복구도 함께 검증하기 위함이다.
2. 두 기기의 APK SHA-256과 연결 화면의 12자리 호환 코드를 기록한다.
3. Android 설정에서 두 기기를 Bluetooth 페어링한다.
4. 두 기기 모두 기내모드를 켠다.
5. Wi-Fi와 모바일 데이터는 끄고 Bluetooth만 다시 켠다.
6. 앱의 주변 기기 권한을 허용한다. 위치 권한은 요구되지 않아야 한다.
7. A 기기를 호스트, B 기기를 참가자로 고정한다.

## P0 시나리오

| ID | 영역 | 절차 | 합격 판정 | 필수 증적 |
|---|---|---|---|---|
| P0-01 | 환경 | 두 기기 기내모드 ON, Wi-Fi·데이터 OFF, Bluetooth ON | 네 조건이 동시에 확인됨 | 양쪽 빠른 설정 화면 |
| P0-02 | 권한 | 권한 초기화 후 앱에서 주변 기기 권한 요청 | Bluetooth 권한만으로 페어링 목록 표시 | 권한 화면, 연결 화면 |
| P0-03 | 호환성 | 두 기기 연결 화면 진입 | 12자리 호환 코드 일치 | 양쪽 연결 화면 |
| P0-04 | 연결·대기실 | A 방 만들기, B에서 A 선택, A에서 협동 원정 시작 | 15초 안에 양쪽 `CONNECTED`, 시작 전 양쪽 대기실 유지, 방장 시작 후에만 동시 전투 진입 | 양쪽 대기실·전투 화면, 소요 시간 |
| P0-05 | 협동 전투 | 각자 카드 1장 이상 선택 후 확정 | 한 번만 해결되고 턴·공동 체력·적 체력이 일치 | 해결 전후 양쪽 화면 |
| P0-06 | 항로 | 서로 다른 개인 항로 선택 | 두 선택이 호스트에서 합쳐져 같은 다음 상태 표시 | 양쪽 지도 화면 |
| P0-07 | 보상 | 전투 승리 후 캐릭터 카드 또는 공용 카드 선택 | 선택 카드가 해당 플레이어 덱에 1장 추가 | 보상·덱 화면 |
| P0-08 | 상점 | 공용 카드 1장 구매 | 골드가 정확히 차감되고 카드가 덱에 추가 | 구매 전후 화면 |
| P0-09 | 이벤트 | 두 기기에서 서로 다른 선택 투표 | 절충 결과가 한 번만 적용되고 양쪽 결과 일치 | 투표·결과 화면 |
| P0-10 | 재접속 | 전투 계획 전 Bluetooth 연결을 끊고 다시 연결 | 20초 안에 같은 턴·체력·손패 복원 | 끊김·복원 화면 |
| P0-11 | 호스트 종료 | P1 계획 확정 후 A 앱 강제 종료·재실행·재연결 | 저장된 P1 계획이 유지되고 중복 해결 없음 | 종료 전후 화면, 로그 |
| P0-12 | 양쪽 종료 | 양쪽 계획 커밋 후 공개 전에 두 앱 강제 종료 | 재실행 후 커밋–리빌을 이어서 다음 턴 진입 | 종료 전후 양쪽 화면, 로그 |
| P0-13 | 결투 | 양쪽에서 서로 다른 카드를 비공개 확정 | 상대 카드가 공개되지 않고 동시 해결 후 내구도 일치 | 확정 전후 양쪽 화면 |
| P0-14 | 모드 격리 | 결투 중 협동 메뉴·명령 진입 시도 후 협동 복귀 | 결투 상태 오염 없이 차단되고 협동 상태 복원 | 차단 안내·복귀 화면 |
| P0-15 | 지속성 | 협동 또는 결투를 30턴 혹은 30분 진행 | 크래시·ANR·불일치 0건 | 시작·종료 화면, 전체 로그 |

## 부정 시나리오

- 다른 호환 코드를 가진 APK 연결: `VERSION MISMATCH`로 차단되어야 한다.
- 두 기기 역할이 잘못된 경우: 역할 안내가 표시되고 게임 명령이 전송되지 않아야 한다.
- 참가자가 확정 버튼을 연속 입력: 같은 턴 계획은 한 번만 커밋되어야 한다.
- 공개 데이터 또는 체크포인트 위변조: 커밋 불일치로 거절되고 턴이 진행되지 않아야 한다.
- 호스트 범위 이탈 후 복귀: 자동 복구되지 않으면 사용자가 다시 연결했을 때 마지막 체크포인트로 복원되어야 한다.

## 로그 수집

각 기기를 USB로 연결할 수 있으면 아래 명령에서 `<serial>`을 실제 시리얼로 교체한다.

```bash
adb -s <serial> logcat -c
adb -s <serial> logcat -v threadtime Godot:I godot:I AndroidRuntime:E ActivityManager:I '*:S'
```

정상 핸드셰이크 로그에는 양쪽에서 다음 형식이 한 번씩 보여야 한다.

```text
SESSION_HANDSHAKE role=host compatibility=XXXXXXXXXXXX
SESSION_HANDSHAKE role=guest compatibility=XXXXXXXXXXXX
```
